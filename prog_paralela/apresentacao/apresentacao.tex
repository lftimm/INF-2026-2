	\item Barnes-Hutt : O(nlog(n))

	\item Cada thread realiza uma quantidade similar de computação.
      \end{enumerate}

\frame{
    \frametitle{Hipóteses Iniciais}
    \begin{enumerate}
      \item Gargalo de 20-21 threads ocorrido por acessos não uniformes na memória.
      \item Latência por acessar a memória próxima do outro processador (NUMA).
      \item Ao aumentar o número de threads e problema, deixa de ser tanto problema.
      \item Mais threads trabalhando trazem mais dados pra próximo do segundo processador.
    \end{enumerate}
}

\frame{
  \frametitle{Discussão dos Resultados}
  \begin{itemize}
    \item A noção que passar para 21 threads traz latência é colaborada pelos eventos.
    \item CPI maior na run de 21 threads demonstra que há mais latência comparado com 20.
    \item Entretanto, a presença de mais números do evento CPU UNHALTED ONE THREAD ACTIVE com 21 threads, traz o hyperthreading como suspeito.
    \item A run de 21 threads também fica bastante tempo parada em uma call do OMP (libgomp), comparada com a de 20 threads.
    \item Evidencia que possa ser não o acesso à memória, mas talvez um núcleo em hyperthreading, atrasando todos os outros núcleos na chamada de barreira.
    \item Um thread lerdo, atrasando os outros.
    \item Explicaria o Speedup retornar a subir quando aumentamos o número de threads, maisdelas estão em hyperthreading, mais threads fazendo trabalho similar, diminuindo o peso da barreira.
  \end{itemize}
